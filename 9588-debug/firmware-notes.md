# 9588 V3.30 / JZ4740 固件依据

此配置来自 C200 原厂内核，不沿用 9688/H1 私有地址。

- 原始 C200.bin：4,652,744 字节；SHA256 `02a16107b11a3281067871c6fe3d4c289c910d8dfa9924573dd87f00351d6525`，加载到 `0x80004000`。
- kj409588.bin 是同一 payload 加 64 字节头；SHA256 `e86ceb0ab4cdf3075fc2086f59641ee12dd8de4d7fcbf2f2c0e24f20dee44321`，没有把包装头当作 MIPS 代码。
- `profiles/9588-jz4740.json` 含 36 个运行守卫和 2 个消息框守卫，记录地址、长度、CRC，不包含原始机器码。`verified` 指静态核对，和硬件验证独立。

运行时先逐项比较五张服务导入表，再核对原厂机器码 CRC；不匹配时拒绝分配堆块、创建任务或接管 USB。仅在 GUI 表及消息框代码独立匹配时显示错误提示。

TCB 的参数、栈底、栈长度、delay 与 priority 分别位于 `+4/+8/+0xc/+0x30/+0x35`，与原厂 TaskCreateExt/TCBInit/调度代码逐项核对。原厂静态创建优先级 7、8、9、62、63；调试器使用 6，并在运行时拒绝占用槽。

原生全局堆范围为 `[0x80880000,0x81c00000)`，运行时服务表头在 `0x81c00000`，原生 BDA 入口在 `0x81c00020`。停止时保留驻留堆块和休眠任务，同版重开可复用；更换构建须重启。TCU1 中断为 IRQ22，调试器只在原始 handler/argument 匹配时安装 tick 包装器，并在停止时恢复。不能使用 9688 的 IRQ 表或 H1 的内存上界。

## 内存、LCD 与 USB

原厂 `loader_9588_4740.bin` 的 SHA256 为 `6220a556a617db932449de4465a64c3179558ffa2173228fa0cb66c32364cd07`。SDRAM 初始化构造 DMCR 几何 `0x041a0000`，结合 JZ4740 手册寄存器定义为 32-bit 总线、9 列、12 行、4 bank：`2^(12+9) × 4 × 4 = 32 MiB`。缓存地址上界是 `0x82000000`；不能将模拟器默认的 160 MiB 配置当作机器容量。

原厂 LCD 为 240×320、16-bit，物理 framebuffer 为 `0x01f82000`。真实 MIPS 描述符构造函数产生自环描述符 `0x00477d10`，source=`0x01f82000`，command=`0xc0009600`，帧长153,600字节。截图读取 DMA 描述符，检查长度/范围/前后稳定性；不把 GUI 镜像对象指针当作 framebuffer。当前 QEMU 原生桌面扫描像素倒置180°，客户端纠正该方向；真机仍待核对。

USB 为 JZ4740 MUSB、IRQ24。原厂 GPIO handler 明确读取 PB18 并进入 UDC_CONNECT/DISCONNECT 路径。调试器保守拒绝已检测连接或被原生服务持有的控制器；物理 VBUS 极性、总线 ACK/重传和 CDC 插拔仍待真机验证。当前完整固件模拟器仅实现无 USB 主机的寄存器状态，不能作为 CDC 收发通过的依据。

JZ4730 的 OST/IRQ23、旧式 UDC 和 GP89 与本配置不同；已有部分逆向不代表完整支持。JZ4730/JZ4720 及其他固件暂不生成运行绑定。

## 验证分层

MIPS/控制器模型实际执行重定位后的 resident、launcher、协议、EXEC 和 LCD 代码，并验证独立重链接及真实 PC 客户端到 MIPS 的帧交换。提供原厂 C200 时58项通过；无固件时仅跳过依赖原始固件的检查。这些模型不能代替完整系统调度或真机。

完整固件模拟器入口诊断另行记录实际工具散列、BDA散列、注入/加载方式和覆盖边界；物理9588未接入本轮验证。原厂固件、NAND、厂商手册与用户数据均不分发。
