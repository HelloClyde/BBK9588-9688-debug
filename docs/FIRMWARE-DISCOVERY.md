# 启动时发现固件地址

源码开发版的 9588 / 9688 Debug 增加了运行时地址发现。已发布的 `alpha.3` 没有这项功能，不能把本页的验证结果用于旧 BDA。

启动先试原有的精确配置；关键机器码 CRC 和 BDA 当前五张导入表都符合时直接启动。精确配置不符合时，再用本地检查过的原厂内核生成的特征库，寻找 **指令布局与板级行为相同、函数或全局变量地址发生变化** 的内核。这个过程不执行待识别的原厂函数。

步骤如下：

1. 读取 BDA loader 现有的 GUI、FS、SYS、MEM、RES 五个导入表，校验指针范围、空槽及固定数据的布局，建立原地址到现地址的约束。
2. 为原厂关键函数核对地址归一后的 MIPS CRC：只有已独立解码的 RAM `J/JAL` 和 `LUI` 加低半字地址操作数可变化。相对分支、任务结构偏移、GPIO 极性、USB/LCD 寄存器及其他指令仍要精确符合。主函数中直接 `J/JAL` 调用的辅助入口另核对最多 64 字节的入口特征；遇到首个 `JR RA` 时包括延迟槽后停止，避免把短函数之后的另一函数当作其入口内容。已知函数体内部的跳转或数据引用还要保持原指令偏移。
3. 根据已经核验的调用和数据引用定位其余函数。未被这些引用定位的根函数，在 `0x80004000..0x80800000` 做一次并行特征扫描。没有唯一目标便拒绝；不会采用“第一个结果”或“离旧地址最近的结果”。原地址到新地址的关系必须一致且单射，防止坏表把多个符号塌缩到同一地址。
4. 从已解码的引用还原任务表、当前 TCB、调度状态、全局堆、tick、IRQ 表、服务表和 LCD 几何地址。IRQ 槽的索引仍由已核对的芯片 IRQ 编号确定。所有必需的地址都要找到，才能继续。
5. 核对当前 TCB 与任务优先级表的对应关系、调度运行状态、原生 USB/tick IRQ 处理函数及参数、LCD 几何，以及固件中唯一的 `9588 OS` 或 `9688 OS` 产品标记。存在另一机型标记也拒绝。产品标记用于机型隔离，不能单独用来推断芯片或板级 GPIO。

launcher 和驻留程序分别执行同样的发现。它们使用固定的 26 个私有 RAM 绑定槽，通过 SoC 和解析结果计算 `binding_id`，启动及复用时必须一致。没有 JZ4730 native endpoint helper 的槽保留为 0，不改变字段顺序。驻留控制 ABI 升为 2；旧版正在后台时，重启设备后再使用新 BDA。

这项功能扩大的是地址变化的兼容范围，并没有取消固件 ABI 依赖。函数被重新编译、结构变化、表项改序、寄存器或接线改变，都可能需要补充特征和独立验证。运行时只调用已经识别的关键入口；直接辅助入口的认证有明确范围，不是整个辅助函数或递归调用树的完整认证。其内部依赖仍须保持原有内核 ABI，这不是对所有固件功能的完整证明。管理功能另有自己的调用入口和 CRC 认证，发现核心绑定不自动开放文件、桌面或输入接口。

## 查询结果

客户端 `python 9588-debug/client.py firmware`（9688 使用同样的命令，将路径中的机型换为 9688） 使用协议操作码 47。响应为 9 个 32 位小端字，随后是 `binding_count` 组 `(index,address)`：

| 字段 | 含义 |
|---|---|
| version | 当前为 1 |
| mode | 0：未识别；1：精确配置；2：运行时扫描 |
| soc | 4720、4730 或 4740 |
| binding_id | 当前绑定身份，用于启动和复用核对 |
| error | 发现阶段的错误码；0 表示成功 |
| binding_count | 实际返回的绑定对数，当前统一为 26 |
| scanned_words | 本次发现读取的扫描词数，精确快路径为 0 |
| matched_functions | 扫描中核验的关键函数数 |
| reference_count | 成功图中的地址映射数 |

绑定索引使用 `discovery_gen.py` 固定的 26 槽顺序；部分芯片没有对应 helper 时以 0 保留槽位，不能按单份配置的字段数推算。客户端同时显示索引、名字与地址。工具记录失败结果后不自动重试有副作用的命令。单独的状态查询也不会以打开另一条 CDC 连接的方式干扰当前操作。

## 特征库生成与验证

`discovery_gen.py PROFILE LOCAL_ROM --write` 只接受与该配置 SHA-256 相符的本地原始内核或 64 字节头包装文件。它生成 CRC、掩码锚点、引用坐标及导出地址元数据，不复制完整固件。日常构建和 CI 使用仓库里的元数据，不需要原厂 ROM。生成后还要审阅原生调用、板级行为与 IRQ 索引；生成脚本的输出不替代这些核对。

新增 `test_discovery` 直接运行编译后的 MIPS 发现代码，验证无原厂字节的合成内核中函数、服务表和全局变量分别移动，并检查单条 `JAL` 操作数损坏或指向辅助函数内部、重复根、指令变化、错误 MMIO 常量、塌缩引用、导入指针越界、运行态结构破坏、缺失或错误产品标记的拒绝。通用 launcher 的扫描失败会清空候选芯片选择并还原默认绑定，另有成功后再失败的回归测试。可选的本地 ROM 测试另核对五份特征库可重建、已知配置快路径，以及原厂关键代码/表/数据整体移动 64 KiB 后的发现结果。

这些地址移动文件是 **发现算法的合成布局测试**：只执行 Debug 自己的扫描代码，没有启动变换后的原厂内核，不构成真实新版固件或 USB 真机验收。完整路径为并行函数特征扫描及产品标记校验，各最多扫一次 8 MiB 范围；诊断中典型为 4,186,112 个扫描词。加入直接辅助入口校验后的本机 Unicorn 诊断运行约需一秒，模型给出 3 亿条指令的终止预算。此耗时不是设备端实测值，也不能用来承诺启动时间。本轮新 BDA 的 9588/JZ4740 原厂完整内核诊断见 [流程验证](WORKFLOW-VALIDATION.md)，明确采用 GDB 诊断传输；历史真机证据仍只对应其确切旧文件。五套新功能的真机 USB 验收尚未补充。
